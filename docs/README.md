# GlintBar technical documentation

How GlintBar is built, how it works, and how to develop on it. For what the app does
and how to install it, see the [main README](../README.md).

## Project layout

GlintBar is a Swift package (`Package.swift`) with three targets, plus tests:

| Target | What it is |
| --- | --- |
| [`GlintBar`](../Sources/GlintBar) | The app: menu bar item, Touch Bar UI, customization window, system controls |
| [`GlintBarPrivate`](../Sources/GlintBarPrivate) | A thin Objective-C shim around the private frameworks GlintBar uses |
| [`GlintBarNowPlaying`](../Sources/GlintBarNowPlaying) | A small dylib loaded into `/usr/bin/perl` to read playback state (see [Now Playing](#now-playing)) |

Inside `Sources/GlintBar`:

- `TouchBar/`: the bar itself. [`BarController`](../Sources/GlintBar/TouchBar/BarController.swift)
  presents it, handles item actions and keeps items up to date;
  [`SliderPanelController`](../Sources/GlintBar/TouchBar/SliderPanelController.swift) runs the
  sliders that pop out of items; [`BarView`](../Sources/GlintBar/TouchBar/BarView.swift) draws
  and lays out everything; the glass buttons, sliders and item views live next to it.
- `Layout/`: the item catalog ([`BarItem`](../Sources/GlintBar/Layout/BarItem.swift)) and the
  saved arrangement ([`BarConfiguration`](../Sources/GlintBar/Layout/BarConfiguration.swift)).
- `Customize/`: the drag-and-drop customization window. Its drop rules are in
  [`BarDropTarget`](../Sources/GlintBar/Customize/BarDropTarget.swift), apart from the view.
- `System/`: audio, brightness, battery, system resources, now playing and other system actions.
- `Icons/`: glyphs drawn in code (the eclipse logo, the battery).
- `Backgrounds/`: the pictures flexible spaces can show
  ([`SpaceBackground`](../Sources/GlintBar/Backgrounds/SpaceBackground.swift)), drawn in code
  (see [Flexible space backgrounds](#flexible-space-backgrounds)).

## Building

Requires Xcode 26+ and macOS 26+.

```bash
./scripts/build-app.sh            # release build, bundled into build/GlintBar.app
./scripts/build-app.sh --install  # also copies it to ~/Applications and launches it
```

The script builds a universal (arm64 and x86_64) release binary, assembles the bundle (copying
`libGlintBarNowPlaying.dylib` into `Contents/Frameworks`) and ad-hoc signs it.
`./scripts/make-dmg.sh` then packages it into `build/GlintBar.dmg`.

### Releases

Publish a release on GitHub with a new version tag (e.g. `v0.2.0`) targeting `main`, without
attaching any files. Publishing pushes the tag, which runs the
[release workflow](../.github/workflows/release.yml): it sets `CFBundleShortVersionString` from
the tag and `CFBundleVersion` from the run number, builds the DMG and attaches it, with its
SHA-256 checksum, to the release a few minutes later.

Pushing just a tag also works; the workflow then creates the release itself, with generated
notes:

```bash
git tag v0.2.0 && git push origin v0.2.0
``` The DMG is only ad-hoc signed,
not notarized; the main README tells users how to get past Gatekeeper.

For quick iteration, run it without a bundle:

```bash
swift build && .build/debug/GlintBar
```

Launch at login is only available when running from the `.app`.

### Tests

```bash
swift test
```

The tests in [`Tests/GlintBarTests`](../Tests/GlintBarTests) cover what runs without the
Touch Bar: item layout, saving and loading layouts, the customization window's drop rules and
reading the now-playing helper's output. CI ([`.github/workflows/ci.yml`](../.github/workflows/ci.yml)) checks formatting, builds and tests every
push to `main` and every pull request.

### Formatting

The Swift code is formatted with `swift format`, which comes with Xcode. Its rules are in
[`.swift-format`](../.swift-format): Apple's defaults, adjusted to the code's own style
(4-space indents, 120-column lines, no extra indent inside `#if`).

```bash
./scripts/format.sh          # formats Sources, Tests and Package.swift in place
./scripts/format.sh --check  # only reports problems; this is what CI runs
```

The check is strict, so any formatting difference fails CI. Run `./scripts/format.sh` before
committing, then fix by hand whatever `--check` still reports (lint rules such as naming that
the formatter doesn't fix).

### Icons

The icon artwork lives in [`Design/Icons`](../Design/Icons) and is generated by
`node Design/Icons/make-icons.mjs`. After changing `app.svg`, run
`./scripts/make-app-icon.sh` to rebuild `Resources/AppIcon.icns`. The menu bar and Control
Strip glyphs are drawn in code from the same geometry
([`EclipseGlyph`](../Sources/GlintBar/Icons/EclipseGlyph.swift)).

## How it works

### One item, system-wide

GlintBar presents a system-modal Touch Bar over every app and registers a button in Apple's
Control Strip so you can get back to it after switching to the app's own controls.

The whole bar is a single Touch Bar item ([`BarView`](../Sources/GlintBar/TouchBar/BarView.swift)).
That way GlintBar controls the layout itself, including the transitions between the main row and
a popped-out slider.

### Private APIs

Most of what the Control Strip does isn't available through public API. All private symbols are
resolved at runtime with `dlopen`/`dlsym` in [`GlintBarPrivate`](../Sources/GlintBarPrivate), so a
missing symbol disables a feature instead of crashing the app.

| Feature | API |
| --- | --- |
| System-wide bar, Control Strip button | `NSTouchBar presentSystemModalTouchBar:…`, `DFRElementSetControlStripPresenceForIdentifier` (DFRFoundation) |
| Display brightness | `DisplayServicesGetBrightness` / `SetBrightness`, `DisplayServicesRegisterForBrightnessChangeNotifications` (DisplayServices) |
| Keyboard backlight | `KeyboardBrightnessClient` (CoreBrightness) |
| Night Shift | `CBBlueLightClient`, including its status notification block (CoreBrightness) |
| Show Desktop | `CoreDockSendNotification` (HIServices) |
| Spotlight, Quick Actions | The distributed notifications Apple's Control Strip posts |
| Media commands | `MRMediaRemoteSendCommand` (MediaRemote) |
| Playback state, seeking | MediaRemote, from inside `/usr/bin/perl` (see below) |
| Volume / mute | CoreAudio (public) |
| Battery | IOKit power sources (public) |
| System Resources | Mach host statistics, the GPU's IOKit `PerformanceStatistics`, volume capacity (all public) |

Because of these APIs GlintBar can't ship on the Mac App Store, and a macOS update can break it.

### Keeping up to date

Display brightness, Night Shift, displays coming and going, volume, battery and now playing
all report their changes. The clock turns over on the minute. What doesn't report changes
is polled every 1.5 s, and only while the configured bar has an item that needs it: the
keyboard backlight (`KeyboardBrightnessClient` has a notification API, but it reports nothing
to GlintBar), whether the audio output's volume can be changed, and whether an app button's
app still exists. All of it pauses while the bar can't be seen (screens asleep, another user's
session in front, app controls showing) and catches up when it can again.

### Flexible space backgrounds

A flexible space's background is part of its saved name (`flexibleSpace:blackHole`), so it
travels with the layout. Each picture is drawn with Core Graphics for the exact width the space
has: the black hole and prism keep their centrepiece at the bar's height and stretch the disk,
beam and spectrum into the room around it, and the sky's stars are scattered tile by tile from
the middle, so they stay put while the space grows or shrinks. Every picture has a minimum
width (`SpaceBackground.minimumWidth`); narrower spaces stay empty.

The Touch Bar and the Customize window render through the same code
(`SpaceBackground.image(size:scale:)`), and only when a space's size changes. On the bar
they're still images, so they cost nothing while it's showing.

### Now Playing

Since macOS 15.4, MediaRemote tells third-party processes that nothing is playing.
[`NowPlayingMonitor`](../Sources/GlintBar/System/NowPlayingMonitor.swift) therefore loads
`libGlintBarNowPlaying.dylib` into the Apple-signed `/usr/bin/perl`, which is still allowed to
ask, and reads its state changes as JSON lines from its stdout. Commands go the other way, as
lines on the helper's stdin: seek requests, and `poll off` / `poll on`, which stop the
helper's safety-net poll while nothing shows playback (MediaRemote's change notifications
still come through) and catch up as soon as something does again. The helper exits when
GlintBar's end of that pipe closes.

## Debug commands

Debug builds accept commands over a distributed notification. This lets you drive the bar
without touching it and capture it with `screencapture -b`:

```bash
osascript -l JavaScript -e 'ObjC.import("Foundation"); $.NSDistributedNotificationCenter.defaultCenter.postNotificationNameObjectUserInfoDeliverImmediately("center.julian.GlintBar.debug", "down:volume", $(), true)'
```

Replace `down:volume` with any of these (x positions are in bar points):

| Area | Commands |
| --- | --- |
| Level sliders | `down:<level>` (or `down:volume:850`), `move:700`, `up`, `tap:<level>`, `close`; levels are `keyboard`, `display` and `volume` |
| Bar state | `appControls`, `glint` |
| Now Playing | `scrub:down`, `scrub:move:<x>`, `scrub:up` |
| Buttons | `press:<item>`, e.g. `press:volumeUp` |
| Battery | `battery:<percent>` (optionally `:charging` or `:power`) fakes the level; `battery:real` undoes it |
| System Resources | `resources:<cpu>:<gpu>:<memory>:<storage>` in percent fakes the readings; `resources:real` undoes it |
| Flexible spaces | `background:<bar index>:<name>` gives the flexible space there a background (`midnightSky`, `blackHole`, `prism`, or `none`) |
| Customization window | `customize`, `snapshot:<png path>` (includes an open popover), `popover:<png path>` (just the popover), `cbackground:<bar index>` opens a flexible space's background picker, `cbackground:off` closes it |
| Customization drags | `cdrag:bar:<index>` or `cdrag:palette:<item>` (`app` for the App tile), then `cdrag:to:<x>` or `cdrag:off`, then `cdrag:drop` |
