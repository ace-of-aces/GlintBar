# GlintBar technical documentation

How GlintBar is built, how it works, and how to develop on it. For what the app does
and how to install it, see the [main README](../README.md).

## Project layout

GlintBar is a Swift package (`Package.swift`) with three targets, plus tests:

| Target | What it is |
| --- | --- |
| [`GlintBar`](../Sources/GlintBar) | The app: menu bar item, Touch Bar UI, customization window, system controls |
| [`GlintBarPrivate`](../Sources/GlintBarPrivate) | A thin Objective-C shim around the private frameworks GlintBar uses |
| [`GlintBarNowPlaying`](../Sources/GlintBarNowPlaying) | A small dylib loaded into `/usr/bin/perl` to read playback state (see [Now Playing](#now-playing)) |

Inside `Sources/GlintBar`:

- `TouchBar/`: the bar itself. [`BarController`](../Sources/GlintBar/TouchBar/BarController.swift)
  presents it and handles item actions; [`BarView`](../Sources/GlintBar/TouchBar/BarView.swift)
  draws and lays out everything; the glass buttons, sliders and item views live next to it.
- `Layout/`: the item catalog ([`BarItem`](../Sources/GlintBar/Layout/BarItem.swift)) and the
  saved arrangement ([`BarConfiguration`](../Sources/GlintBar/Layout/BarConfiguration.swift)).
- `Customize/`: the drag-and-drop customization window.
- `System/`: audio, brightness, battery, system resources, now playing and other system actions.
- `Icons/`: glyphs drawn in code (the eclipse logo, the battery).

## Building

Requires Xcode 26+ and macOS 26+.

```bash
./scripts/build-app.sh            # release build, bundled into build/GlintBar.app
./scripts/build-app.sh --install  # also copies it to ~/Applications and launches it
```

The script builds in release mode, assembles the bundle (copying `libGlintBarNowPlaying.dylib`
into `Contents/Frameworks`) and ad-hoc signs it.

For quick iteration, run it without a bundle:

```bash
swift build && .build/debug/GlintBar
```

Launch at login is only available when running from the `.app`.

### Tests

```bash
swift test
```

The tests in [`Tests/GlintBarTests`](../Tests/GlintBarTests) cover what runs without the
Touch Bar: item layout, saving and loading layouts, and reading the now-playing helper's
output. CI ([`.github/workflows/ci.yml`](../.github/workflows/ci.yml)) builds and tests every
push to `main` and every pull request.

### Icons

The icon artwork lives in [`Design/Icons`](../Design/Icons) and is generated by
`node Design/Icons/make-icons.mjs`. After changing `app.svg`, run
`./scripts/make-app-icon.sh` to rebuild `Resources/AppIcon.icns`. The menu bar and Control
Strip glyphs are drawn in code from the same geometry
([`EclipseGlyph`](../Sources/GlintBar/Icons/EclipseGlyph.swift)).

## How it works

### One item, system-wide

GlintBar presents a system-modal Touch Bar over every app and registers a button in Apple's
Control Strip so you can get back to it after switching to the app's own controls.

The whole bar is a single Touch Bar item ([`BarView`](../Sources/GlintBar/TouchBar/BarView.swift)).
That way GlintBar controls the layout itself, including the transitions between the main row and
a popped-out slider.

### Private APIs

Most of what the Control Strip does isn't available through public API. All private symbols are
resolved at runtime with `dlopen`/`dlsym` in [`GlintBarPrivate`](../Sources/GlintBarPrivate), so a
missing symbol disables a feature instead of crashing the app.

| Feature | API |
| --- | --- |
| System-wide bar, Control Strip button | `NSTouchBar presentSystemModalTouchBar:…`, `DFRElementSetControlStripPresenceForIdentifier` (DFRFoundation) |
| Display brightness | `DisplayServicesGetBrightness` / `SetBrightness` (DisplayServices) |
| Keyboard backlight | `KeyboardBrightnessClient` (CoreBrightness) |
| Night Shift | `CBBlueLightClient` (CoreBrightness) |
| Show Desktop | `CoreDockSendNotification` (HIServices) |
| Spotlight, Quick Actions | The distributed notifications Apple's Control Strip posts |
| Media commands | `MRMediaRemoteSendCommand` (MediaRemote) |
| Playback state, seeking | MediaRemote, from inside `/usr/bin/perl` (see below) |
| Volume / mute | CoreAudio (public) |
| Battery | IOKit power sources (public) |
| System Resources | Mach host statistics, the GPU's IOKit `PerformanceStatistics`, volume capacity (all public) |

Because of these APIs GlintBar can't ship on the Mac App Store, and a macOS update can break it.

### Now Playing

Since macOS 15.4, MediaRemote tells third-party processes that nothing is playing.
[`NowPlayingMonitor`](../Sources/GlintBar/System/NowPlayingMonitor.swift) therefore loads
`libGlintBarNowPlaying.dylib` into the Apple-signed `/usr/bin/perl`, which is still allowed to
ask, and reads its state changes as JSON lines from its stdout. Seek requests go the other way,
as lines on the helper's stdin. The helper exits when GlintBar's end of that pipe closes.

## Debug commands

Debug builds accept commands over a distributed notification. This lets you drive the bar
without touching it and capture it with `screencapture -b`:

```bash
osascript -l JavaScript -e 'ObjC.import("Foundation"); $.NSDistributedNotificationCenter.defaultCenter.postNotificationNameObjectUserInfoDeliverImmediately("center.julian.GlintBar.debug", "down:volume", $(), true)'
```

Replace `down:volume` with any of these (x positions are in bar points):

| Area | Commands |
| --- | --- |
| Level sliders | `down:<level>` (or `down:volume:850`), `move:700`, `up`, `tap:<level>`, `close`; levels are `keyboard`, `display` and `volume` |
| Bar state | `appControls`, `glint` |
| Now Playing | `scrub:down`, `scrub:move:<x>`, `scrub:up` |
| Buttons | `press:<item>`, e.g. `press:volumeUp` |
| Battery | `battery:<percent>` (optionally `:charging` or `:power`) fakes the level; `battery:real` undoes it |
| System Resources | `resources:<cpu>:<gpu>:<memory>:<storage>` in percent fakes the readings; `resources:real` undoes it |
| Customization window | `customize`, `snapshot:<png path>` |
| Customization drags | `cdrag:bar:<index>` or `cdrag:palette:<item>` (`app` for the App tile), then `cdrag:to:<x>` or `cdrag:off`, then `cdrag:drop` |

### Screenshots

The screenshots in the README live in [`images`](images). They were taken with
